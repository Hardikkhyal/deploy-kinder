# Task 9: Backend Planning

The backend is a **Node.js / Express.js** API. It requires deep interaction with the host operating system (Linux shell, Docker daemon).

---

## 1. Folder Structure
```text
backend/
├── src/
│   ├── controllers/     # Route logic (projectController.ts, etc.)
│   ├── routes/          # Express route definitions
│   ├── services/        # Business logic & OS interactions
│   │   ├── dockerService.ts    # Interacts with Dockerode
│   │   ├── gitService.ts       # Executes git clone/pull
│   │   └── nginxService.ts     # Writes dynamic nginx.conf
│   ├── middleware/      # AuthGuard, ErrorHandler
│   ├── models/          # Prisma schema & DB access
│   ├── config/          # Environment variables & constants
│   ├── utils/           # Logger, Crypto helpers
│   └── server.ts        # Express entry point
```

## 2. Core Modules & Services

### **Authentication & Authorization**
- `authMiddleware.ts`: Verifies the JWT in the `Authorization` header. If valid, attaches `req.user`. If invalid, throws a 401 Error.

### **Docker Engine Service (`dockerService.ts`)**
- Uses the `dockerode` NPM package to bind to `/var/run/docker.sock`.
- Contains functions: `listContainers()`, `buildImage()`, `startCompose()`.
- *Crucial detail:* Streams build outputs via `EventEmitter` to the database and frontend.

### **Deployment Engine Service (`gitService.ts`)**
1. Receives webhook or manual trigger.
2. Checks if `/deployments/{projectId}` exists.
3. If no: runs `git clone {url} .`
4. If yes: runs `git fetch && git reset --hard origin/{branch}`.
5. Emits events to update the Deployment Status in the DB to "BUILDING".

### **Nginx Configuration Module (`nginxService.ts`)**
- When a project starts on port `X` (e.g., 8001), the backend writes a file to `/etc/nginx/sites-available/{projectId}`.
- Example template generated by Node:
  ```nginx
  server {
      listen 80;
      server_name {project_name}.devopshub.local;
      location / {
          proxy_pass http://localhost:8001;
      }
  }
  ```
- Node then executes `ln -s` to `sites-enabled` and runs `systemctl reload nginx`.

## 3. Configuration & Environment Variables
Use `dotenv` to manage secrets. Required `.env` file:
```env
PORT=4000
DATABASE_URL="postgresql://postgres:password@localhost:5432/devopshub"
JWT_SECRET="super_secure_random_string_do_not_commit"
DOCKER_SOCKET_PATH="/var/run/docker.sock"
NGINX_CONF_PATH="/etc/nginx/sites-available"
```

## 4. Error Handling
- A global Express error handler `app.use((err, req, res, next) => {...})` intercepts all unhandled promises.
- Custom `AppError` class extends native `Error` to include HTTP status codes.
- All Docker CLI failures are caught, logged to the DB as "FAILED", and the user is safely notified without crashing the Node server.
